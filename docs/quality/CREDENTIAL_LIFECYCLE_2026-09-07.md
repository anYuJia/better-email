# 登录凭据生命周期修复与验收

基线：v1.0.55，e3b93396f39f486c56355a8e3f94242f4d1d11a9。

## 证据范围

用户反馈“已登录，但统一邮箱同步提示未保存授权码”。错误出现在本机凭据读取路径，不是邮件服务商返回的认证拒绝。源码能够确认下述缺陷；没有读取用户本机数据库、密钥或诊断日志，不能据截图判定实际设备究竟经历了哪一次写入失败、旧版迁移或数据目录变化。测试与公共 PR 不包含用户真实邮箱、授权码或本机数据。

历史版本移除系统凭据库时未将旧凭据自动取回本机数据库。保持该隐私约定：本次不在启动或设置页访问 Keychain，不自动提取或上传旧系统凭据。

## 已实现

| 范围 | 改动与约束 |
| --- | --- |
| 新账号持久化 | 新 UI 将授权码与账号一起交给 create_account。账号、默认文件夹、身份和加密凭据在同一个 IMMEDIATE 事务中写入，读回解密核验后才提交。账号独立创建的旧入口也事务化。空授权码不能完成 UI 登录。 |
| 验证路径一致 | 新账号和重新登录使用 verify_account_credentials，从已持久化凭据读取；不再用输入框中的临时内容绕过存储验证。输入专用诊断命令为兼容旧调用保留，但不作为持久化成功依据。 |
| 验证过程 | 保存后的服务器登录验证放入最多四个并发的阻塞工作任务。验证结束重读本机凭据与服务器配置；改变或删除后，旧验证结果作废，不能显示为有效登录。 |
| 本机健康检查 | 返回 not_found、key_missing、unreadable、invalid、exists，区别不存在、无法解密和认证格式不匹配。exists 只证明本机可读，不声称服务器验证成功；检查不联网、不刷新 OAuth、不创建密钥、不删除数据。 |
| 密钥保护 | 当数据库已有账号或 AI/MCP 密文时，后续写入必须使用现有密钥，缺失或损坏直接失败，不能因添加账号或保存 AI 配置生成新密钥掩盖故障。保留原文件和密文。 |
| 保存结果可靠性 | 凭据 upsert 后读回并解密比较；失败回滚原值。账号 ID 和认证方式可显式绑定，拒绝过期表单写入已删除或不同认证方式的账号。 |
| 设置交互 | 同一轮重复点击合并为一次操作；失败不清空输入，不执行登录验证；切换账号、卸载或编辑新内容后，迟到的结果不能覆盖新状态或清除新输入。保存账号设置也不再把用户切回旧账号或丢掉较新的未保存修改。 |
| 恢复入口 | 邮件列表显示持续的本机凭据问题和“修复登录”。桌面独立设置窗口带上受影响账号 ID；内嵌设置等待切换到目标账号再打开登录页。无需删账号重建。跨窗口事件、窗口重新获得焦点和定时检查刷新本机健康状态。 |
| 多账号调度 | 在限额批次前检查凭据；不可读的账号单独记录 credential_issues，不占据可用账号的名额。统一同步仍明确报告这些账号失败，不把跳过当作全部成功。所有账号均不可用时暂停定时入队并定期重查。手动同步失败、部分完成或批次受限不再显示“已是最新”。 |
| OAuth 账号边界 | 授权会话、会话列表、回调监听、交换和刷新显式绑定设置中所选账号，不再默认刷新/保存到默认账号。认证期间切换账号不展示旧结果或清空新账号输入。 |
| OAuth 写入竞态 | 自动和手动刷新比较原凭据快照后才保存，不覆盖重新登录的新值、不复活已删除凭据。交换结果与会话完成状态在同一事务提交，失败保留授权会话；迟到失败不能降级已完成会话。回调只消费 pending 状态。 |
| 测试真实性 | mock 的已保存状态和验证结果关联，未保存凭据不能得到虚假的验证成功。所有本机/网络结果保持语义区分。 |

## 自动化覆盖

前端用例覆盖：空输入、读回接口错误、新建后验证抛异常、重复提交、持久化后才验证、UI 后处理失败不删除已验证账号、失败保留输入、切换账号期间迟到成功/失败、健康检查过期响应、恢复入口账号定位、OAuth 非默认账号绑定、保存设置不覆盖新表单。

## 仍需真实环境验收

1. QQ/其他密码账号：保存并验证→完全退出→重新打开→读取正文、同步、发送。缓存邮件和账号 ID 保持不变。
2. 多账号：非默认账号修复，另一个账号正常同步；设置窗口切换、快速重复点击和验证期间更改凭据。
3. 密钥故障：有密文但 key 缺失/损坏时，检查和新写入都不生成替代密钥；恢复原备份后可读。真正缺失的凭据无法从账号元数据还原，需在应用内重新输入。
4. OAuth：目标账号与服务商一致，过期令牌、手动重认证、多个窗口同时刷新、回调超时、网络结果不确定。比较更新保护本机持久化，不等同于解决所有服务商的多进程 refresh-token 轮换；仍需端到端验证。
5. Android 真机软键盘、系统字号、窗口恢复与后台挂起；Windows/macOS 原生 WebView、数据目录升级与备份恢复。

本次不是整个邮件客户端无 Bug 的证明。已有完全丢失的密码无法恢复；不建议删除账号、数据库或 credentials.key。未实现无备份时自动轮换整个密钥库，避免破坏其他账号或 AI/MCP 的密文。新账号验证异常时仅回滚本次新建账号，不把已存在账号作为删除重建的恢复手段。
